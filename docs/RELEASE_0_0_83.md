## 真机定位

对实际手机中的41个会话进行只读切换采样，UI状态约13,174,156字符：

- 原点击处理器同步执行完整 persist，三次保存分别约822、639、828 ms。
- 首次缓存长历史的渲染约653 ms。两个切换的处理器/首帧分别1526/1545 ms、722/733 ms。
- 当时分页历史请求约38–88 ms，说明主要阻塞在本地保存和渲染，不能将本次迟钝归因于模型生成速度。

## 修改

- 会话选择不再调用同步完整 persist。新增延后合并的 saveNavigationLater，原生存储队列仅更新活动会话/项目元数据；不在WebView线程等文件锁，不传输聊天正文。利用现有保存版本排序，防止较旧选择覆盖更新后的完整快照；pagehide/后台切换刷新待保存选择。旧宿主保留完整保存兼容路径。
- 点击会话/侧栏删除入口先绘制选中/忙碌反馈，再执行切换。连续快速点击只执行最后一次仍有效的目标。
- 打开已保存会话先展示对应标题、输入框和加载状态，等待现有分页历史读取后只更新信息流，避免先渲染庞大缓存、随后再重建整页。默认显示最近5回合，可继续加载更早回合；不删除内核历史。
- 历史请求成功/失败与执行过程补读均检查当前会话、设置状态及路由，不能在用户进入设置后把设置页替换成聊天；请求代次防止A→B→A时旧结果清理新请求的状态。
- 历史回填保持当前输入框节点，避免覆盖切换后输入的草稿；活动详情补读按当前会话增量保存，避免请求整份UI状态保存。
- 删除确认显示归档/保存阶段，有未落盘内容时优先等待异步完整检查点，保留失败与运行中保护。归档结果晚到时，不关闭用户后来打开的新弹窗；用户已经切换到另一对话时，不把页面跳回删除对象。
