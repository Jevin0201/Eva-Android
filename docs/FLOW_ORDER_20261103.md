# 0.0.36 · 信息流状态位置

截图中的“正在思考”出现在上一段工具记录和最新用户消息之间。根信息流的 updateKernelFlow 原先只把新 section 追加到末尾，不重新排列已经存在的 section。先产生 response-status 再加入下一回合时，实际 DOM 成为“旧回合 → 状态 → 新回合”，而期望顺序是“旧回合 → 新回合 → 状态”。

改为按 desired 顺序以 insertBefore 移动既有节点，保留消息节点、流式正文和展开状态；滚动定位继续使用既有锚点逻辑。修复不限于“正在思考”，同样覆盖待提交消息、审批和其他根节点的排列。

## 验证

先添加失败回归，在原实现复现实际 DOM 顺序错误；修复后通过。

- 新回合出现时，已存在的状态节点移动到最新用户消息后，且边界几何位置正确。
- 待提交消息、同回合引导消息均排在思考状态前，状态仅一份。
- 既有回合、状态和流式回答节点保持同一 DOM 对象。
- 工具进度互斥、审批阻塞、结束清理，以及发送／删除和任务控制回归通过。
