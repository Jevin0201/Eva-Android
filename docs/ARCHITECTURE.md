# 需求与架构候选

## 已确认需求

1. 手机独立运行 Eva，保留云端模型调用方式。
2. 打开、观察并精细操作安卓 App，支持跨应用任务。
3. Eva 自带浏览器，支持网页结构读取、点击、输入、多标签、登录状态与上传下载。
4. 本地文件和项目工作区，支持 Node.js、Python、Git 等开发工具。
5. 编程、运行、排错、构建 APK，并在安装后检查应用表现。
6. 保留统一任务上下文、执行反馈、中断与恢复能力。
7. 与桌面 Eva 使用独立项目目录。

## 候选架构（未定案）

Android 原生宿主管理生命周期、权限、手机控制、浏览器与本地执行服务。Eva 的任务内核通过工具桥接调用这些能力。

- 手机控制：控件树、截图、手势、输入、应用启动和切换；评估无障碍及 Shizuku 增强能力。
- 浏览器：Android WebView 加专用控制层；将网页观察、元素操作、上传下载统一为任务工具。
- 执行环境：优先验证内置 PRoot + Ubuntu ARM64；比较 Termux 原生工具链的兼容性与成本。外部 Termux 可作为调试或备用后端。
- 终端服务：会话 ID、命令 ID、流式输出、退出码、超时、取消、工作目录与进程生命周期管理。
- 文件桥接：统一逻辑工作区路径，明确安卓侧与 Linux 侧映射、导入导出和授权。

不预设必须单 APK 或双 APK；由运行时兼容性、升级和进程管理验证决定。不能将复制运行时二进制视作已解决安卓执行限制。

## 实施顺序与验收

### 1. 内核与运行环境

盘点现有 Eva 执行内核及桌面依赖，验证候选环境中的真实会话、流式响应、文件修改、命令执行、工具调用、取消与恢复。记录设备型号、安卓版本、环境版本与失败项。

### 2. 手机与浏览器工具

在同一任务中打开 App、定位控件、输入并检查结果；在 Eva 内置浏览器完成页面操作和下载，将下载文件交给本地命令处理。

### 3. 开发闭环

创建项目、安装依赖、运行与排错、构建 APK、经系统安装流程安装、打开并检查界面。Android SDK/ARM64 构建工具需独立验证，不能由 Node.js/Python 可运行推导。

### 4. 产品化

环境初始化与升级、磁盘空间管理、任务保存与恢复、权限引导、浏览器状态持久化，以及界面关闭或系统回收后的恢复行为。

## 尚未解决的问题

- Eva 当前执行内核在目标安卓 Linux 环境中的兼容性。
- 目标手机与安卓版本、权限配置以及后台任务限制。
- WebView 的复杂页面、登录、跨域框架和文件交互覆盖率。
- Linux 与安卓文件桥接、原生依赖及 APK 构建工具链。
- 第三方模块许可证和可维护性。
