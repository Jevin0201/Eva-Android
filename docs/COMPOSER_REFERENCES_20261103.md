# 技能与插件的显式对话调用（2026-11-03）

依据桌面 composer-input.js 和 composer-references.js 核对：技能使用 type=skill、name、SKILL.md path；插件使用 type=mention、name、plugin://ID。仅输入一个匹配名称不等于结构化调用。

本次实现：
- 插件详情和技能详情有“应用到对话”；未安装/停用插件、停用技能不可应用。
- 输入框有“技能与插件”选择入口；@ 检索插件与技能，$ 仅检索技能，支持中文输入法完成后检索、键盘方向/Enter/Escape、空列表和失败提示。
- 选择保存在当前草稿 references，并以可删除标记显示；新草稿不复用已有选择的空草稿。
- turn/start 和 turn/steer 均携带结构化输入，发送前按当前项目重新读取可用目录，失效项阻止派发，失败保留原文及选择。
- 接纳后仅清除本次发送的选择；不自动重试任务。
- 原生浏览器/办公快捷项是 builtin 用户选择，以明确的用户文本指令提交，不伪造尚未安装的 skill/plugin 路径。具体执行仍依赖模型、工具权限与办公依赖。
- 目录缓存按项目分隔，15 秒复用，不在每次输入时重复请求目录；发送前强制核对。

验证：test-composer-references 覆盖 @ 选择、两种协议输入、失败保留、停用阻止发送、标记移除、草稿隔离和详情页应用返回对话；发送/插件/技能/统一列表/运行中追加指令/滚动/全局事件回归通过。APK 构建通过并覆盖安装。

这是选择器及真实请求格式的实现与模拟协议测试。未对用户实际插件进行安装/卸载，也未宣称每个第三方服务已完成账号授权或端到端云任务验收。MCP 服务器的工具仍由启用配置暴露给模型，本轮没有伪造 MCP 为插件 mention。
