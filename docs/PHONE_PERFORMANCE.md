# 手机执行性能优化（2026-11-03）

## 已实现

- 直接启动：`open_app` 支持准确应用名称或包名；按名称唯一匹配后调用 Android 启动 Intent，省去桌面识图导航。同名返回候选，不猜测启动。`apps.query` 可缩小列表。
- 控件优先：仅传递可见、有意义的控件，省略默认布尔值和装饰节点。操作后自动附带新观察，减少模型再次调用 observe 的往返。Android 13+ 读取前清理无障碍缓存，避免短等待时读到旧内容。
- 输入连接：没有可编辑节点时，通过 Android 无障碍输入连接提交 Unicode；观察结果提示 `focusedInputAvailable`。校验应用身份及密码类型，不自动执行发送。
- 视觉兜底：没有可读标签时附带最长边 1280px 图片；明确请求 screenshot 时保留 1920px。新空窗口只短暂重试一次，已知空窗口不重复等待。截图期间窗口改变则重新观察，不重放操作。
- 等待由固定 180ms 改为有上限的 UI 事件安静期等待。工具结果包含 queueMs/actionMs/elapsedMs，便于区分本地排队、执行和模型延迟。
- 内置浏览器输入、点击、导航后返回新 DOM 与快照；只重试观察，不重复执行点击，观察有超时边界。

这些是系统公开接口、无障碍和输入连接的组合，没有获取 root，也不能直接调用微信未开放的内部业务接口。

## 真机验证

M332BF / Android 17，安装本次 APK 后，在 Eva 自有测试页测量（单次样本，非端到端任务基准）：

| 项目 | 结果 |
| --- | --- |
| 读取控件树 | 18ms，5 个节点，824 字节结果 |
| 节点输入并返回新观察 | 52ms |
| 点击并返回新观察 | 67ms |
| 首次无控件页面观察与截图 | 188ms |
| 同一无控件页面再次观察与截图 | 45ms |
| 自动截图 / 详细截图大小 | 13,673 / 24,637 字节 |
| 详细截图最长边 | 1920px |
| 准确名称启动 Eva、未知名称拒绝 | PASS |
| 中文和 emoji 无节点输入、应用与密码校验 | PASS，输入及观察 129ms |
| 浏览器连续输入/点击、新快照、旧快照拒绝、最小化视口、截图 | PASS |

`PhonePerformanceCheck` 同时验证旧快照不会重放操作。初次测试发现旧控件缓存，刷新缓存后通过。安装导致服务重连期间一次检查被取消，待连接稳定后重跑通过。

## 使用与范围

APK 已通过 `tools/build-probe.ps1` 构建并安装。测试入口为 ShellActivity 的 `phone-performance-check`、`phone-input-check`、`browser-check`。测试不向第三方应用发送消息。

新工具参数与说明在新建会话时注册；已有会话仍享受原生执行优化，但可能保留旧工具说明和参数。当前内核 `thread/resume` 协议不支持覆盖 dynamicTools，因此验证完整的新策略请新建会话。

保留原有模型推理设置。以上毫秒数只代表手机执行层；云端推理、网络、应用动画和页面加载仍影响整条任务耗时，尚未测得第三方应用完整任务的前后对照数据。
