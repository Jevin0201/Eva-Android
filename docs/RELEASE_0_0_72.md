真机复现了“更多”按钮点击后菜单延迟出现导致下一步零匹配的问题。批处理现在在 step.timeoutMs（默认 3 秒）及全局截止时间内等待目标出现，每次重新观察并检查取消和包名变化。歧义或其他错误立即停止，等待不会重放已执行动作。open_app 的 app 字段支持精确已安装包名，保留重名候选检查。

原生路线检查 30 项、批处理检查 19 项通过。真实 OpenAI 模型学习“返回→更多→设置”，保存新路线 aba2fc0b-8352-4225-9643-f3c144e5b468，绑定 com.miui.calculator / 17.4.1 / 317000041，三步实际回放并 confirm verified=true。证据位于 artifacts/acceptance-0.0.72/app-replay-fixed-turn.json。

## DSH 失败原因与修复

实际项目为 https://github.com/Ebony-Vinyl/dsh-our-free-model ，项目许可证 MIT。手机已经安装其 standalone 2.7.1 源码和独立数据。原对话曾遇到 Git Proxy CONNECT aborted，随后使用源码归档完成下载并跑通单次调用，但接入当前 Eva 仍未完成。模型修改的是手机工作区中的 0.0.61 旧源码，实际安装版已是 0.0.71，因此没有覆盖安装。

本轮确认并修复以下问题。

- Eva 提供商原先只支持 HTTPS。现在允许数字回环地址的 HTTP，Android 网络策略仅为回环放行。服务自产凭据由原生接入入口读入 Keystore，完整模型列表持久保存。更换地址或凭据清除旧目录，空刷新保留旧目录，过期请求不能覆盖新配置。
- 模型菜单展开每个提供商的全部模型，新聊天保留所选模型。刷新目录与换选模型不再作为内核凭据变化要求重启。原生模型配置及 Keystore 回归、Chrome 模型选择回归通过。
- 手机冷启动后服务端口未监听。选择该本机提供商时自动确保服务运行，复用现有源码和数据，并检查健康状态。PRoot 持续跟踪 Node 子进程，不能用进程退出判断常驻服务就绪，现改为本次随机握手及真实 health 双重确认。代理变更只重启经过命令行归属检查的受管实例；外部未受管实例明确要求先停止后接入。
- standalone 的 Responses 转换在每次响应中重复生成 msg_0、fc_0 等编号，导致同回合多请求的消息和工具记录覆盖。兼容补丁按 response ID 为 item.id/call_id 加入唯一前缀，保留同响应内所有流事件及后续工具回传的一致引用。

兼容补丁只接受已核验的 src/forward.js 原 SHA-256 7f0d6fa748985bda19eb6536d444eea5151ac243a33f6b2883292d249867e1b6。原文件保存在手机项目数据 eva-compat 目录，原子替换、重复执行与未知修改拒绝均有回归。源码备份、原项目、配置和模型凭据保留。补丁不会覆盖未知修改的源文件。

流式及非流式跨请求唯一编号、同响应事件一致性、function_call_output.call_id 回送已执行真实转换函数离线回归。真机已读到 24 个模型，冷启动后 kilo-auto/free 在 Eva 内核正常回复，并实际执行 Python 得到 42、退出码 0。编号补丁后的多次模型请求已观察到 msg_resp-*/fc_resp-* 独立记录。免费上游存在可用性与模型执行差异，未验证每个模型的完整手机任务能力。

通用 GitHub 安装指引补齐了项目格式识别、ARM64/PRoot 环境检查、独立目录、锁文件、服务生命周期和实际入口验收。不同项目仍需按其平台和依赖实测，不能将本次 DSH 适配推为全部 GitHub 项目兼容。
