# 2026-11-05 消息发送保存失败

> 以下为首次现场热修复记录。后续已改用完整SQLite事务存储，取消临时详情删减，并恢复构建环境；最新状态见 [Codex研究与升级](CODEX_UPGRADE_20261105.md)。原签名仍缺，未覆盖安装。

## 真机根因

ShellActivity.Bridge.saveValue 拒绝超过 2,000,000 Java 字符的 UI 状态。当前内存状态实测为 2,126,350 字符。kernelSend 在 thread/start 或 turn/start 前同步保存，因此所有对话（包括新对话）都会被同一份全局超限快照阻断。界面出现 android/storageError；这不是此次故障的模型网络超时。

## 修复

统一四个 UI 保存入口的序列化：小快照保持原样；超过 1,500,000 字符时，对有原生 thread ID 的已完成回合压缩大型 dynamicToolCall 的参数及返回内容缓存，显示重新加载说明。完整工具历史仍在原生线程存储，通过重新打开对话读取。用户消息、助手回答、草稿、项目、正在执行的工具及导入只读历史不压缩。仅序列化副本，不修改运行中的数据对象。

这仍受旧原生桥 2,000,000 字符上限约束；若纯文本/导入历史本身超过上限，仍应报告失败，不能绕过发送前持久化。后续需要独立的分会话存储迁移，不能仅无限提高 SharedPreferences 上限。
