# 0.0.28：模型接入、发送延迟与真机回归

## 本轮处理顺序

1. DeepSeek 对话阻断与发送到内核执行前的等待。
2. 桌面三档执行权限、手机端子智能体实际调用。
3. 悬浮浏览器与后方页面交互；手机控制断开恢复、停止、跨 App。
4. 桌面模型选择与推理强度、生命周期与信息流、单一灵动岛进度。
5. 项目重命名/删除、移除会话右上角设置按钮。
6. 构建安装与完整能力盘点，明确未交付项。

## 已定位的原因与修改

- 普通聊天错误地申请手机控制所有权，陈旧 owner 会阻断文本发送。改为只有实际手机工具调用取得独占权，任务结束释放。
- thread/start 与 turn/start 使用了不同提供商配置。按会话提供商调度并同步内核配置；密钥只进入 native 环境变量。
- 提供商配置中的 `deepseek-v4.1-flash` 不在实测 `/models` 结果中。保留原地址与加密密钥，改用服务返回的 `deepseek-flash`；旧会话可通过选择器切换。
- 全局事件没有 threadId 时误匹配未初始化草稿，触发“信息流事件处理失败”。按明确线程 ID 分发，保留提前到达的增量。
- 原生默认启用未接入的云 apps/MCP/plugin 发现，手机网络超时阻塞任务准备。Android 启动配置关闭这部分未接入的发现，手机/浏览器动态工具继续可用。
- 剩余固定 5 秒来自 Git 提交署名配置查询：已登录的 ChatGPT 认证被第三方模型进程一并加载，每轮初始 world-state 等待 backend user settings。现在 API 模型运行在独立进程、使用内核支持的 ephemeral auth store；ChatGPT 认证文件保留，原会话存储共享，旧线程可以继续恢复。
- Native 事件主动通知 WebView，32ms 合并刷新并保留轮询兜底；前台恢复预热内核。耗时诊断仅记录阶段/时间/域名，不记录提示词或密钥。

源码依据：桌面 Eva 0.2.0 的 composer/model-catalog、官方 Codex `ext/git-attribution/src/policy.rs` 和 `login/src/auth/storage.rs`。上游诊断源码下载在 `downloads/codex-source-diagnostics`，没有把这些 Rust 文件作为产品依赖或修改手机内核二进制。官方源码与实际固定超时/认证隔离对照测试共同支持原因判断。

## 模型控件与项目

- 提取桌面模型控件函数、SVG、菜单 CSS，原文件和 SHA-256 记录在 `migration/eva-0.2.0-model-control`。Android 只适配持久化、弹窗定位和 native bridge。
- DeepSeek 支持 low/high/max，保留推理能力；模型目录按桌面逻辑从本机原生目录合并，使用 direct 工具模式，不继续依赖 unknown-model fallback。
- 项目菜单支持重命名与删除，名称重复/空值与保存失败都有处理。删除项目只移除分组，关联对话进入“最近”，原工作目录、附件及对话保留。确认页明确说明这一语义。
- 移除对话页右上角设置入口，设置仍在侧栏底部。
- 去掉自绘的无障碍悬浮进度条，操作文字进入 Android 实时通知/灵动岛；完成摘要在同一通知更新，后台控制通知仍可停止任务。是否提升为灵动岛由系统与用户设置决定。

## 尚不能算完整交付

- ChatGPT 工作区发现当前在手机网络上超时；不能把保留登录文件等同于当前账号调用成功。
- 手机构建 APK 所需 Java/Gradle/aapt2/d8/apksigner 尚未就绪。电脑构建并安装本 APK，不等于手机独立构建验收。
- 浏览器上传/下载及网站权限的完整链路未交付。
- 手机自助下载初始化运行时、完整升级/回滚、长时间后台与重启压力测试未完成。
- Android PRoot 下 workspace-write 的 bubblewrap 挂载隔离仍不能建立；请求批准/帮我批准会先遇到隔离错误，再经正常授权流程重试。未伪装隔离成功，也未静默降级为完全访问。完全访问模式没有该次失败重试。
- DeepSeek 当前使用原生 V1 子智能体协议；子智能体可进行分析与内核任务，但该内核的 V1 不继承 Eva 的手机/浏览器动态工具。手机和浏览器操作仍由主智能体执行。

## 权限与子智能体的兼容修复

三档菜单来自桌面 `util.js` / `composer.js`，映射为原生参数：请求批准为 on-request/user/workspace-write；帮我批准为 on-request/auto_review/workspace-write；完全访问为 never/user/danger-full-access。选择按会话及默认值保存，运行中禁止更改，内核返回策略不一致则停止发送。审批 ID 保留原始类型并区分两个认证进程，不将审核失败自动变成批准。

DeepSeek 自动审核最初失败，原因是合并模型目录后使用了 OpenAI 的 `codex-auto-review`。根据原生 `ext/guardian-reviewer/src/model.rs` 支持的 `auto_review_model_override`，自定义模型改用自身作为审核模型，保留完整审核策略。修复后的真机测试确认审核完成并执行成功。

新版 V2 子智能体的 `agent_message_from_tool` 在普通直接函数调用缺少 `encrypted_function_args: []` 时按加密消息处理。DeepSeek 发送的明文任务因此没有进入子任务的用户消息。适配为该模型的原生 V1 协议，并取消全局强制 V2；其他模型继续按照模型目录选择协议。真机验证了两个独立子线程中的真实用户任务、独立完成消息与父线程汇总，并非界面模拟。

展示迁移记录在 `migration/eva-0.2.0-permissions`、`migration/eva-0.2.0-subagents`。子线程事件、历史读取、提前到达的增量和父子归属均经过回归。生命周期/信息流保留桌面 stream-state 和处理阶段投影，Android 负责原生事件路由、持久化和窗口生命周期，不能把共享渲染代码等同于所有移动端生命周期已自动正确。

本轮通过模型选择、权限、子智能体、项目管理、全局事件、信息流阶段、发送/删除、滚动、侧栏、设置及导航回归。最后一次构建成功并覆盖安装到连接的手机；原生手机所有权和悬浮浏览器触摸测试在安装后再次通过。

追加的原生控制页手动停止界面测试未完成：直接 ADB 打开非 exported Activity 被 Android 拒绝；随后准备经应用自身入口打开的工具调用被自动审批审查以 `blocked by policy` 拦截，未给出更具体原因，未继续该操作。既有安全测试页的停止后拒绝访问，以及最终构建的所有权/禁用控制检查已通过，不能以此替代完整界面与长时间后台验收。
