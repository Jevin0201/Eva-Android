# 0.0.28 后续修订：登录、草稿、键盘、模型同步与浏览器窗口

## 登录状态

原生账号页通过 `nativeRequest` 更新缓存，但网页账号面板直接走 RPC，没有更新同一缓存；全局账号变更也没有完整同步。现在在账号进程的消息接收端统一处理账号读取结果、登录完成和账号变更通知。API 模型独立进程的未登录状态不会清除 ChatGPT 登录。

连接失败不等于退出。UI 区分保存的登录记录与连接检查失败；真实退出或内核确认无账号仍会更新状态。返回前台的账号检查有去重与节流，读取模型不再串行等待额度网络请求。初始化失败会清理对应进程，退休进程的迟到消息不再覆盖新进程状态。

令牌仍由内核保存和续期，没有复制、输出或自行保存 OAuth 令牌。协议依据：[官方 App Server 账号文档](https://learn.chatgpt.com/docs/app-server)。

## 草稿与模型

- 未发送内容保存在独立 `drafts` 集合；只有内核接受真实回合才提升为正式对话。重复点击新聊天不产生最近列表空项，发送失败保留草稿，附件不移到另一个新草稿。
- 旧空项迁入草稿，不删除用户内容。有内容的草稿可在“查找对话”中按文字搜索，标注“未发送草稿”。
- 提供商默认模型变更同步至仍跟随旧默认的聊天/草稿，手动选择的其他模型保持，执行中的任务延后同步。历史消息不改写。
- 已知错误型号 `deepseek-v4.1-flash` 仅在官方 DeepSeek 地址、后台配置为 `deepseek-flash` 时精确迁移；第三方同名模型不受影响。去掉人为生成的旧型号显示名。

## 验收记录

草稿发送/失败/重复创建/查找、模型变更/已知错误迁移、发送删除、模型面板、侧栏、权限和全局事件回归已通过。原生账号状态测试使用独立测试偏好，不触及真实账号；实际账号检查只读取账号类型与缓存是否一致，不输出身份或令牌。

发送过程中切走的草稿也可从查找入口返回。发送前保存原生线程 ID，重建时先读取原生历史，不自动重发；已收到回合接纳事件、但确认响应超时的发送，不再恢复成可重复发送的原文。

## 键盘与浏览器

- 新增“收起键盘”按钮并连接原生 IME；系统返回先收起实际可见的键盘，无键盘时保留页面原返回行为。
- 浏览器从独立 Activity 改为 ShellActivity 持有的非模态 Dialog。旧 Activity 仅兼容转发，避免最小化后仍作为独立前台页面占据交互。
- 保留网页内容与视口，最小化不抢输入焦点；宿主页恢复时恢复浏览器状态。

最终构建覆盖安装到设备 509655c7，以下原生测试通过：

| 检查 | 结果 |
|---|---|
| AccountStateCheck | 登录事件/读取同步；API 实例隔离；连接错误保留状态；明确退出清除偏好；不触及真实凭据 |
| AccountReadCheck | 真实账号已登录，内核与缓存一致；最终复测耗时 1.635s |
| KeyboardCheck | 物理点击收起按钮与系统 Back 均关闭真实 IME，草稿保持，后续导航可用 |
| BrowserWindowCheck | 展开/最小化后方真实触摸；原生工具页面往返；重进主页面；输入框焦点；网页及视口保留 |

键盘测试首轮受到 instrumentation 定向输入不能注入系统 IME 的限制；改为系统级测试返回键注入后通过，收起按钮仍以应用真实触摸验证。

以上验证不等于长期网络断开、令牌过期与多日后台压力测试已完成；本轮没有退出用户账号或要求重新登录。浏览器旋转/长时间后台仍不扩大声明为已验收。
