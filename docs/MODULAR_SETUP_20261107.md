# 首次启动与按需组件部署

开始于 2026-11-07，收尾于 2026-11-08。用户保留现有约 345 MB APK 的方案，确认首次启动采用两步设置；本轮实现代码并生成同版本 0.0.72 的独立候选 APK，没有覆盖手机原正式 Eva。

## 使用流程

1. 首次打开显示「准备好，开始使用 Eva」。用户确认后才部署必备环境，显示阶段、进度与错误，支持重试。基础镜像仍内置，必备联网依赖为 procps-ng；自检覆盖 Node 执行、Python SSL/SQLite、Git 与 Codex。原先 6 GiB 的全工具链门槛不再用于必备部署；解压仍按清单实际大小检查临时空间。
2. 核心就绪后显示「还想让 Eva 做些什么？」。办公、开发、媒体全部默认不选；可以直接配置模型并开始使用。REA 与 Ghidra 在专业工具中分别选装。设置增加「能力与组件」入口。

办公包含基础生成库、LibreOffice、PDF 工具、中文字体和用于制品渲染的 Linux Chromium；手机浏览器仍是 Eva 内置浏览器。开发包含原生编译工具、Java 17、Gradle 与 Android SDK。Ghidra 才安装 Java 21 与其原生编译工具。REA 不再连带部署 Ghidra，也不会重写已有 MCP 配置。

各组件独立记录就绪、失败、中断与进度。安装逐项进行，单项失败不改变核心就绪状态；取消等待当前受管依赖步骤结束后停止后续步骤。旧全量 ready.json 与用户配置保留，现有依赖不自动卸载。

聊天通过 eva_components status/ensure 检查与请求组件。缺失时显示只包含本次组件的确认页，等待用户选择；安装成功后向原调用返回 ready=true。用户暂不安装返回 ready=false，不允许用终端绕过确认。后台无法直接弹窗时提供通知；无通知权限且不在前台时返回 requiresForeground，让用户先返回 Eva。进程重建后的过期请求不声称原任务仍在等待。

原生 Office 排版预览和 APK 构建页也接到组件安装入口。基础 Office 内容预览、PDF/Markdown/HTML 阅读保持原有本机实现；不要求为了阅读全部安装开发或分析工具。

当前显示清单中的基础镜像大小、解压大小及实际可用空间。可选组件尚未提供精确的新增下载量和最终安装体积；确认页明确其取决于仓库版本及已装共享依赖，没有填入未经测量的数据。

新流程没有把办公、开发、REA、Ghidra 每一组选装都重新完整下载一遍。既有完整工具链的历史实测见 0.0.70 记录；本轮不得把它替代为所有新分组选装都已通过。其他机型和系统版本仍待验证。后台通知分支已实现，本轮主要实测前台确认路径。

构建期间发现同一工作区存在并发修改，构建脚本检测后拒绝签名不一致输入。最终从一份校验一致的冻结源码构建；冻结源码、输入清单、最终 APK 与构建日志保留在证据目录，方便复现。

## 六类文件预览

按用户要求由独立子智能体在原正式 Eva 0.0.72 中制作并预览，未重启或覆盖原应用。手机原文件在 `/root/eva-workspace/Eva-Preview-Showcase-20261107/`；本机文件、ZIP、六类截图及报告在 `artifacts/file-preview-showcase-20261107/`。

统一运营主题包含 Word 两页、Excel 两工作表与原生图表、三页 PPT、两页 PDF、带表格/代码/图片的 Markdown、响应式 HTML。Word/Excel/PPT 的排版预览实际通过本机引擎转换为 PDF；并检查部分后续页。静态 HTML 与 Markdown 实际阅读通过。

已发现而未在本轮修改：横向 Excel/PPT 排版 PDF 在竖屏整页适配时文字偏小，原生 PDF 尚无缩放手势；HTML 顶栏按钮挤占文件标题。Office 内容预览并非完整原版式，排版预览不验证动画播放。
