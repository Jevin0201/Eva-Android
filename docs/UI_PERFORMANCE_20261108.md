# UI 交互性能优化

## 处理范围

1. 新增结构增量保存：项目重命名/删除、对话删除和侧栏折叠，仅发送项目、索引、侧栏和活动会话等元数据。原生 SQLite 事务复用既有会话分块，不遍历、重新哈希和写入整份会话内容。删除从旧索引中移除的会话块与索引在同一事务完成，工作区文件不操作。
2. 本机数据库或会话块尚未就绪、旧格式重复/空 ID 时回退完整保存。有未落盘的草稿、待保存/正在保存的会话内容或原生异步全量保存尚未完成时也保留完整保存，避免优化丢失正文。保存失败仍保留 UI 数据并允许重试，未用异步 fire-and-forget 替代删除成功确认。
3. 删除非当前对话、修改/删除项目只更新侧栏及项目上下文标签，保留当前聊天 DOM、草稿和滚动状态。删除当前对话仍重建相应主页面。对话删除先显示进度，再等待真实内核归档；没有把归档失败吞掉或假报成功。
4. 普通设置页使用 settingsBasic，避免每次进入都执行磁盘空间/rootfs 检查；工作区与存储页继续读取真实完整状态。
5. 原生公共模型配置按供应商配置原文及账号配置快照缓存；任一实际配置变化自动失效。只缓存原有脱敏返回，不向网页增加凭据字段。JS 相同返回不重复解析和遍历目录。

## 检查与数据

- `tools/test-ui-performance.cjs`：100 会话 fixture 的完整数据 1,987,280 字节量级字符串，结构载荷 1,359，减少约99.93%；检查项目操作和非当前对话删除保留聊天节点、草稿、失败回退、未保存内容走完整保存、设置普通页不做磁盘查询。结果见 `artifacts/performance-20261108/results.json`。
- `tools/UiStructureProbe.java`：通过 app_process 在手机 `/data/local/tmp/eva-ui-perf-20261108*` 独立目录执行 SQLite 实测，不打开正式应用数据库、不安装或替换 Eva。检查缺失数据库回退、事务提交、正文/草稿与分块保留、删除块移除、缺失/重复索引事务回滚。
- 同手机100会话约2 MB暖数据库5次采样：完整保存中位数 66,058 微秒，结构保存 4,598 微秒，约14.4倍。只是此存储操作的基准，不能宣称全应用响应提速14倍。日志见 `artifacts/performance-20261108/device-storage.log`。
- 全项目 Java 编译通过；项目管理、默认模型、侧栏、Android 返回和 >2M 完整数据保留回归通过。空 ID 回退与回滚已在手机独立 SQLite 中补验。

## 边界

本轮没有构建/覆盖安装正式 APK。浏览器为模拟宿主；手机实测仅独立 SQLite 路径。需要新版安装后继续测真实数据下点击、删除、设置进入的端到端延迟。完整保存回退和真实内核归档仍可能耗时，没有通过取消数据保护减少等待。

临时编译与 dex 集中于 `artifacts/performance-20261108/`；测试完成清理，保留源码、日志和结果。手机独立测试目录完成检查后移除。项目现有 APK、依赖和其他任务产物保留。
